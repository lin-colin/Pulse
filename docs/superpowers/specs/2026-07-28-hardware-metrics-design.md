# Pulse 硬件指标修正设计

## 目标

修正 Pulse 的系统负载、电池温度和内存压力，使每个指标来源明确、单位正确、失败状态可见。设计以指标真实性和可解释性优先，不追求与 AlDente 的私有实现逐位一致。

## 范围

本次修改包括：

- 系统负载改用 `AppleSmartBattery.PowerTelemetryData.SystemLoad`。
- 电池温度改用 `AppleSmartBattery.Temperature`。
- 内存压力改用 macOS `/usr/bin/memory_pressure -Q` 返回的系统可用百分比进行归一化。
- 默认动态刷新间隔从 3 秒改为 1 秒。
- 内存压力最多每 5 秒采集一次并缓存。
- 指标采集在串行后台队列执行，系统命令最多等待 2 秒。
- 功耗、温度或内存压力读取失败时显示 `—`。
- 添加纯计算和输出解析测试。

本次不包括：

- SMC `PSTR`、`TB0T`–`TB2T` 或 IOReport 私有接口。
- CPU 使用率和 CPU 频率重构。
- 分项 CPU、GPU、ANE、DRAM 功耗。
- Git 提交、应用签名、安装或发布。

## 指标定义

### 系统负载

- 展示名称：`系统负载`
- 原始字段：`PowerTelemetryData.SystemLoad`
- 原始单位：毫瓦
- 展示单位：瓦
- 换算：`watts = milliwatts / 1000`
- 有效范围：有限数且大于等于 0
- 失败行为：返回无值，界面显示 `—`

不使用以下逻辑：

- `InstantAmperage × Voltage`
- 固定 `0.93W` 损耗补偿
- `1.5W` 最低值
- 失败时返回 `5W`

### 电池温度

- 展示名称：`电池温度`
- 原始字段：`Temperature`
- 原始单位：百分之一摄氏度
- 展示单位：摄氏度
- 换算：`celsius = raw / 100`
- 有效范围：`-20...100°C`
- 失败行为：返回无值，界面显示 `—`

`VirtualTemperature` 不再作为电池物理温度的首选值。

### 内存压力

活动监视器没有公开 0–100 的压力公式。Apple 说明其图形综合考虑空闲内存、交换活动、锁定内存和文件缓存。Pulse 使用系统工具输出建立一个可解释的归一化百分比：

1. 执行 `/usr/bin/memory_pressure -Q`。
2. 解析 `System-wide memory free percentage: N%`。
3. 计算 `pressure = 100 - N`。
4. 将结果限制在 `0...100`。

该值命名为“内存压力”，但实现注释必须明确它是基于系统可用百分比的归一化值，不声称复刻活动监视器的私有绘图算法。

采集失败、进程退出码非零、输出格式异常或数值越界时返回无值。最近一次有效结果最多缓存 5 秒，以减少进程启动频率。

## 数据流

每次刷新执行以下流程：

1. 主线程防止重复采集后，将本轮任务派发到串行后台队列。
2. `HardwareMonitor` 读取一次 `AppleSmartBattery` 属性字典。
3. 从同一属性快照提取系统负载和物理电池温度，避免跨快照不一致。
4. `SystemMonitor` 返回缓存内存压力；缓存超过 5 秒时调用系统工具更新。
5. 采集 CPU 和电源状态。
6. 仅将最终 `StatusBarController` 更新切回主线程。
7. `StatusItemView` 和下拉菜单将无值格式化为 `—`。

应用默认每 1 秒刷新。用户仍可选择 1、2、3、5 或 10 秒。

## 代码结构

### `Pulse/Services/HardwareMonitor.swift`

- 新增统一的 `HardwareSnapshot` 数据结构。
- 使用一次 IORegistry 属性读取生成快照。
- 系统负载和温度保持可选值。
- 删除经验公式和虚假兜底值。

### `Pulse/Services/SystemMonitor.swift`

- 内存压力改为解析 `/usr/bin/memory_pressure -Q`。
- 将输出解析提取为纯函数，便于测试。
- 增加基于单调时钟的 5 秒缓存和 2 秒命令超时。
- 提供测试读取器注入点，验证缓存命中与边界。
- 保留现有 CPU 代码，本次不扩展范围。

### `Pulse/App/AppDelegate.swift`

- 默认刷新间隔改为 1 秒。
- 使用串行后台队列采集并防止慢任务重复排队。
- 每次刷新读取一个统一硬件快照。
- 不再把温度无值转换为 `0`。

### `Pulse/UI/StatusBarController.swift`

- 系统负载、温度和内存压力参数改为可选值。
- 下拉菜单无值显示 `—`。
- 菜单标签从“系统功耗”改为“系统负载”。

### `Pulse/UI/StatusItemView.swift`

- 三个硬件指标使用可选值。
- 菜单栏无值显示 `—`。
- 只有存在有效数值时才执行温度和压力颜色判断。

### `Pulse/Models/MetricCalculations.swift`

- 放置无平台副作用的单位换算、范围校验和 `memory_pressure` 输出解析函数。
- 由生产代码和测试共同使用。

### `tests/MetricCalculationsTests.swift`

- 使用独立 Swift 测试可执行程序验证纯函数。
- 覆盖正常值、边界值、缺失字段、非法格式和越界输入。

## 错误处理

- 硬件服务不存在：快照中的相关值为无值。
- IORegistry 读取失败：相关值为无值。
- `SystemLoad` 缺失、负数、非有限数：系统负载为无值。
- `Temperature` 缺失或超出物理合理范围：温度为无值。
- `memory_pressure` 无法启动、退出码非零或输出无法解析：内存压力为无值。
- 所有无值在 UI 中显示 `—`，不得转换为看似正常的数值。

## 测试策略

测试先于实现，执行红—绿—重构流程。

自动测试覆盖：

- `5270mW` 转换为 `5.27W`。
- `0mW` 合法，负功率和非有限值无效。
- `3100` 转换为 `31°C`。
- 温度合理范围边界与越界行为。
- `91% free` 转换为 `9% pressure`。
- `0% free` 和 `100% free` 边界。
- 缺失百分号、非数字、越界百分比和不相关输出解析失败。
- 无值格式化为 `—`。
- 共享默认刷新间隔固定为 1 秒。
- 内存压力缓存命中、5 秒到期和负时间差失效。

集成验证覆盖：

- `build.sh` 编译成功。
- Pulse 同机输出与当前 `PowerTelemetryData.SystemLoad` 和 `Temperature` 一致。
- 内存压力与 `100 - memory_pressure -Q` 一致。
- 菜单和状态栏在无值状态下不显示 `0W`、`0°C` 或伪造值。
- 默认刷新间隔为 1 秒，用户选择其他间隔仍然生效。
- `memory_pressure` 运行期间不会阻塞主线程，且最多等待 2 秒。

## 验收标准

- 系统负载不再由电流与电压重算。
- 项目中不再存在 `+0.93W`、`max(1.5, ...)` 和读取失败返回 `5W` 的逻辑。
- 电池温度使用 `Temperature`，而非优先使用 `VirtualTemperature`。
- 当前机器在低压力状态下显示约 9–10%，而非约 47%。
- 无效指标统一显示 `—`。
- 菜单与定时器使用同一个默认刷新间隔。
- 慢速或异常的内存压力命令不会卡住菜单栏 UI。
- 所有新增测试通过，应用构建通过。
- 不自动提交 Git。
