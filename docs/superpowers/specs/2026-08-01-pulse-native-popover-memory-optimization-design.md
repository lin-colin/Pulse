# Pulse 原生弹出面板与低开销重构设计

## 1. 目标

本次重构同时满足以下目标，任何一个都不能以牺牲另外两个为代价：

1. 菜单栏固定采用 2×2 指标结构，四项内容在正常与极端数值下均完整显示。
2. 详情面板采用接近 macOS“系统设置”的分组行、系统材质和原生控件。
3. 刷新间隔可通过鼠标和键盘可靠操作，开机启动状态与系统真实状态一致。
4. 删除重复手绘、重复硬件快照和高频临时图像分配，降低稳定运行开销。
5. 用清晰边界、真实行为测试和少量集中组件提高可维护性。

## 2. 已确认的产品行为

- 点击菜单栏按钮打开原生 `NSPopover`，点击面板外部自动关闭。
- 详情不再使用传统 `NSMenu` 承载交互控件。
- 菜单栏始终展示系统负载、内存使用、电池温度和 CPU 使用四项 2×2 内容。
- 详情展示系统负载、电池温度、内存使用、内存压力、CPU 使用和电源状态六行指标。
- 控制组包含刷新间隔与开机自动启动两行。
- 刷新间隔支持 `1、2、3、5、10` 秒，当前默认值继续由 `PulseDefaults` 统一提供。
- 退出操作保留 `⌘Q` 快捷键。

## 3. 视觉设计

### 3.1 菜单栏

- 保留当前紧凑 2×2 结构，不将指标缩写成轮播或按优先级隐藏。
- 每次更新文本后先测量两列中最长值，再计算视图固有宽度并同步更新 `NSStatusItem.length`。
- 状态栏按钮保持系统原生选中背景，内容视图不自行绘制常驻胶囊底色。
- 使用 9 pt 等宽数字系统字体和缓存的 SF Symbols，确保数字变化时列宽稳定。

### 3.2 详情面板

- 面板内容宽度固定为 340 pt，根视图使用 `NSVisualEffectView` 自动适配浅色、深色和辅助功能设置。
- 指标组采用约 30 pt 行高；控制组采用约 44 pt 行高。
- 每行由 15 pt 左侧系统图标、13 pt 常规标题和 13 pt 半粗等宽数字值组成。
- 标题不附加冒号，数值靠右对齐并保留足够的稳定间距。
- 分组使用系统设置式圆角背景和组内分隔线，不叠加多层边框或重复灰底。

### 3.3 刷新间隔控件

- 真正的选择行为由原生 `NSPopUpButton` 处理，包括点击、键盘操作、选中状态与弹出菜单。
- 常态下数值区域透明，只有上下箭头带独立圆形浅灰背景。
- 鼠标进入热区后，数值与箭头共同出现宽圆角浅灰背景，箭头不再叠加独立圆底。
- 自定义容器只负责 `mouseEntered`、`mouseExited` 和背景状态，不接管选择菜单。

## 4. 架构与组件边界

### 4.1 `StatusBarController`

负责创建 `NSStatusItem`、处理按钮点击、显示或关闭 `NSPopover`、同步开机启动真实状态，以及把快照传给两个展示入口。它不再创建承载复杂视图的 `NSMenuItem`。

### 4.2 `StatusItemView`

负责格式化后的四项 2×2 展示、颜色状态和动态固有宽度。SF Symbols 在初始化或状态变化时复用，不在每次绘制中复制并染色新图像。

### 4.3 `PopoverContentView`

集中构建指标组、控制组和退出行。使用 `NSBox`、`NSTextField`、`NSImageView`、`NSPopUpButton` 与 `NSSwitch` 等原生 AppKit 控件；固定宽度面板采用确定性行布局，数据更新只修改既有控件内容，不重建整棵视图树。

### 4.4 `RefreshIntervalControl`

独立封装原生 `NSPopUpButton` 与常态/悬浮背景，避免让详情面板同时承担选择器事件和绘制职责。它不覆写 `mouseDown`，也不创建嵌套菜单。

### 4.5 删除的旧视图

完成迁移后删除以下手绘实现及其构建引用：

- `MainMenuView.swift`
- `MetricsCardView.swift`
- `SettingsControlCardView.swift`
- `PopUpSelectView.swift`

新视图必须明显少于被删除实现的总复杂度，禁止保留“旧实现备用”形成双轨代码。

## 5. 数据流与刷新生命周期

1. `AppDelegate` 从唯一计时器收到刷新信号。
2. 串行后台队列在 `isRefreshInProgress` 保护下采集一次硬件快照、一次内存快照、一次 CPU 快照和一次电源快照。
3. 采集结果组成单一展示快照并返回主线程。
4. 主线程用同一快照更新菜单栏与弹出面板，避免两个入口显示不同时间点的数据。
5. 刷新间隔变更先经过允许值校验，再持久化并替换唯一计时器。
6. 详情关闭时不创建额外采集任务；再次打开时立即展示最近一次快照。

## 6. 明确的开销优化

### 6.1 电源读取合并

当前 `BatteryMonitor.powerSourceState()` 先读取一次描述列表，又分别调用会再次读取列表的 `isCharging()` 与 `isPluggedIn()`，单轮最多创建三份 IOKit 快照。重构后单轮只读取一次，并在内存中派生充电、插电和展示状态。

### 6.2 图像与绘制分配

删除三个文件中重复的 `NSImage.tinted(with:)` 实现。详情行使用模板图像与 `NSImageView.contentTintColor`；菜单栏缓存符号配置并直接复用，避免每秒复制着色图像。

### 6.3 视图复用

弹出面板及其行控件只创建一次。指标刷新只更新字符串、颜色和必要的宽度，不创建新的菜单、菜单项、视图或追踪结构。

### 6.4 采集约束

保留串行刷新队列与单任务保护。内存压力事件源和 SMC 连接保持常驻复用；禁止为了降低表面常驻对象数而在每秒刷新中反复创建系统连接。

### 6.5 硬件回退按需读取

当 PSTR 功率和 TB0T 电池温度均通过范围校验时，AppleSmartBattery 不会提供更优结果，因此不再读取整份 IOKit 属性字典。只有任一 SMC 指标缺失时才读取电池注册表并执行降级，避免正常路径每秒产生大量临时桥接对象。

## 7. 内存基线与验收标准

2026-08-01 的基线取证结果：

- 运行约 40 分钟后 physical footprint 为 26.4 MB。
- 基线峰值为 84.1 MB，但峰值本身不能说明当前仍持有同量内存。
- `leaks` 报告总计 14.1 KB，展示的循环属于 macOS AppIntents/XPC 系统对象，没有证据表明 Pulse 自有类型泄漏。
- 默认堆约分配 8 MB；图形相关区域存在可压缩的缓存和分配，但 AppKit 框架驻留不能通过删除业务代码全部消除。

因此不以某个脱离操作系统版本的绝对值作为唯一承诺，采用以下可重复标准：

1. 关闭详情面板运行 15 分钟，第 20 分钟 physical footprint 相对第 5 分钟增长不超过 2 MB。
2. 连续打开和关闭面板后，内存回落并稳定，不出现持续阶梯式增长。
3. `leaks` 报告中不出现 Pulse 自有类型。
4. 优化后的稳定 physical footprint 不高于相同环境下的当前基线，并记录实测结果。
5. 电源描述快照从每轮最多三次降为一次；高频绘制不再复制着色图像。

## 8. 错误处理

- 缺失指标显示“—”，不得伪装为零。
- 刷新间隔只接受允许集合；缺失、非法或损坏偏好值回退共享默认值。
- `SMAppService` 注册或注销失败时，开关立即恢复系统真实状态并记录错误。
- 慢采集期间的新计时信号直接跳过，禁止后台任务无限排队。
- 面板打开时展示最近一次完整快照；部分读取失败只影响对应字段。

## 9. 测试设计

### 9.1 纯逻辑测试

- 菜单栏宽度在长功耗、三位数百分比和不可用值下均按最长列计算。
- 刷新间隔允许值、非法值回退和持久化语义。
- 单份电源描述快照对充电、插电、使用电池和未知状态的派生结果。
- 所有既有指标、SMC、内存压力和格式化测试继续通过。

### 9.2 AppKit 行为测试

- `NSPopUpButton` 的选项变化触发一次间隔回调。
- hover 进入和退出只改变背景状态，不替代原生控件动作。
- 开机启动操作失败后开关回滚。
- 状态栏内容变长时固有宽度与状态项长度同步增加。

现有只比较硬编码常量、未触达真实生产代码的伪 UI 测试将删除或改写，避免用断言数量掩盖覆盖空洞。

### 9.3 完成前验证

- 运行 `./test.sh`。
- 使用 warnings-as-errors 对全部 Swift 源码执行类型检查。
- 运行 `./build.sh` 并校验应用 `Info.plist`。
- 实机验证菜单栏四项完整显示、刷新菜单可点击、hover 两态、开机启动切换和 `⌘Q`。
- 在相同系统与刷新间隔下重新执行 5/20 分钟物理内存对比和泄漏检查。

## 10. 非目标

- 不新增更多硬件指标、图表、历史存储或第三方 UI 框架。
- 不引入 SwiftUI 仅用于复制系统设置外观。
- 不承诺跨 macOS 版本完全相同的绝对内存数字。
- 不自动提交或推送 Git。
