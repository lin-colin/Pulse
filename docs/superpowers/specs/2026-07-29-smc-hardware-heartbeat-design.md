# Pulse SMC 硬件心跳指标设计

日期：2026-07-29

## 背景与根因

Pulse 当前直接把 `AppleSmartBattery.PowerTelemetryData.SystemLoad` 从毫瓦换算为瓦。该字段在电池放电时量级合理，但在充电时会把适配器输入和充电功率叠加，不能解释为“系统自身负载”。

现场充电采样显示：

- `SystemLoad` 固定为 `79.283 W`；
- 同一时刻 SMC `PSTR` 在 `7.38–9.15 W` 之间逐秒变化；
- AlDente 1.36.2 二进制包含 `PSTR`、`TB0T`、`systemLoad` 和 `_systemLoadRaw`；
- AlDente 页面显示的系统负载约为 `9.98 W`。

因此，Pulse 的高功耗显示是数据源语义错误，不是真实硬件功耗，也不是 UI 刷新频率问题。

## 目标

Pulse 的“系统负载”和“电池温度”应作为硬件心跳展示：

- 使用实际硬件传感器值，不添加经验常量；
- 每秒读取并显示传感器变化；
- 充电和放电时保持相同的指标定义；
- 数据源不可用时明确显示不可用，不伪造零值或估算值；
- 指标口径尽量与 AlDente 对齐，但不承诺不同应用在不同采样时刻显示完全相同的小数。

## 数据源

### 系统负载

主数据源为 Apple SMC 键 `PSTR`：

- 含义：Total Board Power，整机主板当前功率；
- 单位：瓦；
- 数据类型：SMC `flt `；
- 刷新：随 Pulse 的一秒刷新周期读取；
- 访问方式：只读打开 `AppleSMC` IOService，不写入任何 SMC 键。

### 电池温度

主数据源为 Apple SMC 键 `TB0T`：

- 含义：电池包温度传感器；
- 单位：摄氏度；
- 数据类型：由键元数据决定；当前机器为 `flt `，其他机型可能为 `sp78`；
- 目的：与 AlDente 使用的传感器测点对齐。

`TB1T` 和 `TB2T` 不参与平均。当前目标是稳定、明确地展示一个与 AlDente 一致的测点，而不是定义新的复合温度。

## 降级策略

### 系统负载降级

1. `PSTR` 是首选值。
2. 当 `PSTR` 不可用且设备明确由电池供电时，允许回退到 `PowerTelemetryData.SystemLoad`。
3. 当设备连接外部电源或正在充电时，禁止回退到 `SystemLoad`，因为该字段在此状态已被证实会包含充电功率。
4. 外部电源状态未知且 `PSTR` 不可用时，返回无值。
5. UI 继续用 `—` 表示无值。

不会使用“适配器输入减去电池功率”作为回退，因为这些属性可能来自不同更新周期，不能保证能量守恒计算的瞬时准确性。

### 电池温度降级

1. `TB0T` 是首选值。
2. `TB0T` 不可用或超出合理范围时，回退到 `AppleSmartBattery.Temperature / 100`。
3. 两个数据源均不可用时返回无值。

## 代码结构

### `SMCReader`

新增只读 SMC 服务，职责限定为：

- 打开和关闭 `AppleSMC` 连接；
- 查询指定四字符键的信息和字节；
- 根据每个键返回的元数据解码 `flt ` 与 `sp78`；
- 提供 `PSTR` 和 `TB0T` 的可选数值。

该类型不包含 UI、降级策略或经验修正。

### `MetricCalculations`

增加纯函数，用于：

- 校验 SMC 功率和温度是否为有限、合理的数值；
- 根据外部电源状态选择 `PSTR` 或安全回退；
- 根据可用性选择 `TB0T` 或 BMS 温度。

纯函数使充电回归场景无需真实硬件即可测试。

### `HardwareMonitor`

一次刷新中：

1. 读取 SMC `PSTR` 和 `TB0T`；
2. 读取一次 `AppleSmartBattery` 属性字典；
3. 获取 `ExternalConnected`、旧 `SystemLoad` 和 BMS `Temperature`；
4. 调用纯函数产生最终快照。

SMC 与电池注册表无法形成原子硬件快照，但不进行跨源功率运算，因此微小的采样时差不会制造错误功率。

## 数值校验

- `PSTR` 必须有限且位于 `0...500 W`；
- `TB0T` 和 BMS 温度必须有限且位于 `-20...100 °C`；
- 超出范围的数值视为数据源不可用；
- 不对功率做平滑、补偿或偏移，保留硬件心跳变化。

`500 W` 只用于拒绝明显损坏的数据，不用于截断合法值；超过上限时返回无值。

## 测试

新增或调整纯函数测试，至少覆盖：

1. `PSTR` 有效时始终优先使用；
2. 充电或外接电源时禁止使用旧 `SystemLoad`；
3. 电池供电且 `PSTR` 不可用时允许旧字段回退；
4. 电源状态未知时不进行旧字段回退；
5. `NaN`、无穷、负数和异常大功率被拒绝；
6. `TB0T` 有效时优先；
7. `TB0T` 无效时回退 BMS 温度；
8. `flt ` 与 `sp78` 解码得到预期值；
9. SMC 连接或键读取失败不会造成崩溃。

## 构建与现场验收

完成实现后必须：

1. 运行项目测试脚本；
2. 以警告作为错误进行类型检查；
3. 运行正式构建脚本；
4. 在充电状态逐秒对照 Pulse、SMC `PSTR/TB0T` 和原始 `SystemLoad/Temperature`；
5. 确认 Pulse 不再显示包含充电功率的 70–80 W；
6. 确认系统负载随 `PSTR` 每秒变化；
7. 确认不包含 SMC 写操作；
8. 不执行 Git 提交。

## 约束与风险

`AppleSMC` 是 macOS 非公开 IOKit 接口。Pulse 当前为非沙盒独立分发应用，可以采用只读访问，但此方案不保证符合 Mac App Store 审核要求。系统更新或硬件型号变化可能导致某些 SMC 键不可用，必须依靠上述可选值和降级策略安全处理。

每次 SMC 调用必须同时验证 IOKit 返回码、SMC 协议结果和完整 80 字节响应。
持久连接若在运行中失效，当前版本会安全返回无值，需重启 Pulse 才会重新建立连接；
该限制不会触发外接电源状态下的旧字段回退。
